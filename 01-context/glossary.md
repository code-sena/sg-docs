# Guardian Escolar - Domain and Technical Glossary

> Shared terminology for the Guardian Escolar school transportation platform. Use these definitions consistently in requirements, UX/UI, APIs, database entities, code, and tests.

| Term | Definition | Synonyms | Notes |
|------|------------|----------|-------|
| Guardian Escolar | Academic SENA ADSO project, cohort 3145556, for managing, monitoring, and improving school transportation safety in Neiva, Huila, Colombia. | School transport platform | Product name. |
| Parent/Guardian | Adult responsible for one or more students and authorized to consult their transportation information. | Acudiente, parent | Can view assigned routes, stops, vehicle status, notifications, and alerts. |
| Student | Minor transported through the school transportation system and associated with a family, route, and stop. | Estudiante | Student data requires special privacy protection. |
| Family | Group or relationship structure connecting students with their parent/guardian or responsible adults. | Familia | Managed through the UserManagement area. |
| Driver | Person responsible for operating an assigned school transportation vehicle and route. | Conductor | May be associated with license information and route assignments. |
| Vehicle | Bus or other authorized school transportation unit used on a route. | Bus, vehicle | Managed by FleetManagement. |
| Route | Planned school transportation path connecting a school or destination with stops and assigned vehicles/students. | Ruta | Managed by RouteManagement. |
| Stop | Location where students board or leave a school transportation vehicle. | Parada | A route can contain multiple stops. |
| Route assignment | Relationship connecting a route with a student, vehicle, driver, or stop. | Assignment | Includes route-bus and route-student assignments. |
| Boarding event | Record or operational event indicating that a student boards a vehicle. | Abordaje | May generate a notification or alert. |
| Drop-off event | Record or operational event indicating that a student leaves a vehicle at a stop. | Descenso | May generate a notification or alert. |
| Route start | Event indicating that a vehicle has begun its assigned route. | Inicio de ruta | May be communicated to guardians. |
| Route completion | Event indicating that a route has finished. | Finalización de ruta | May be communicated to guardians. |
| Delay | Route condition in which the vehicle is later than the expected schedule. | Retraso | Can trigger a notification or alert. |
| Route deviation | Condition in which the vehicle leaves the expected route path. | Desviación | Safety-related event requiring monitoring and communication. |
| Incident | Operational or safety event affecting a vehicle, route, driver, student, or stop. | Incidente | Requires traceability and an appropriate response process. |
| Alert | High-priority or safety-related communication generated by an event or operational condition. | Alerta | Managed by AlertManagement when implemented. |
| Notification | User-facing message about route activity, delay, deviation, incident, boarding, drop-off, or other relevant event. | Notificación | The mobile Notifications view currently uses mocked data. |
| Vehicle location | Current or last known geographic position of a vehicle. | GPS location | Depends on a location provider and API contract. |
| Monitoring | Observation of route progress, vehicle status, location, and operational events. | Monitoreo | Core product priority. |
| Traceability | Ability to know what happened, when, and in relation to which user, vehicle, route, or event. | Audit trail | Core safety and accountability concept. |
| Administrator | Operational role that manages users, families, drivers, buses, routes, stops, and related data. | `ADMIN` | Uses `/dashboard-admin` and `/admin/*`. |
| Superadmin | Global administrative role with access to administrator and school management, plus the shared profile flows. | `SUPER_ADMIN` | Uses `/dashboard-superadmin` and `/superadmin/*`. |
| Authentication | Process of verifying a user's credentials before access. | Sign-in, login | Backend Security module exposes `POST /api/login`. |
| Authorization | Process of deciding whether an authenticated role can access an operation or screen. | Access control | Current Angular routing does not declare `canActivate`; backend or guards must enforce it. |
| IAM service | Microservice for authentication, JWT, RBAC, sessions. | IAM | `09-microservices/services/02-iam-service/` (ADR-008). |
| UserManagement | Backend module for people, families, family members, drivers, and related user data. | User management | Includes endpoints such as `/api/person` and `/api/family`. |
| FleetManagement | Backend module for buses and fleet-related operations. | Fleet management | Includes `/api/bus`. |
| RouteManagement | Backend module for routes, stops, and assignment relationships. | Route management | Includes `/api/route`, `/api/stop`, and assignment endpoints. |
| SchoolManagement | Backend module for schools, campuses, courses, and course groups. | School management | Includes `/api/school`. |
| AlertManagement | Backend module for alerts and saved alerts. | Alert management | Supports the alert domain. |
| BoardingManagement | Backend module for boarding-related records and events. | Boarding management | Supports boarding and drop-off traceability. |
| Dashboard | Main role-based management screen. | Panel | Current dashboards are `/dashboard-admin` and `/dashboard-superadmin`. |
| Profile | Screen where an administrator or super administrator views personal information and starts data-change flows. | Profile information | Route: `/admin/informacion`. |
| Email change flow | Multi-step process for changing the authenticated user's email. | Change email | Route family: `/admin/change-email/*`. |
| Password change flow | Multi-step process for changing the authenticated user's password. | Change password | Route family: `/admin/change-password/*`. |
| Contact change flow | Multi-step process for changing the authenticated user's phone/contact data. | Change contact | Route family: `/admin/change-contact/*`. |
| Navigation Map | Documentation defining screens, routes, roles, backend modules, and user flows. | Navigation map | File: `12-ux-ui/navigation-map-guardian-escolar.md`. |
| Design System | Documentation defining visual tokens, themes, components, UX patterns, and accessibility rules. | Visual system | File: `12-ux-ui/design-system-guardian-escolar.md`. |
| CardList | Shared frontend component for displaying management records as cards. | Management card | Supports students, parents, drivers, families, buses, stops, routes, administrators, and schools. |
| CardRegister | Shared frontend component used for record creation when no specialized form exists. | Registration card | Part of the shared card system. |
| Confirmation modal | Dialog requiring explicit user confirmation before an accepted or irreversible action. | Confirmation dialog | Implemented through components such as `Confirmations` and `DeleteRecord`. |
| Reactive Form | Angular form using controls, validators, touched states, and programmatic validation. | Angular Reactive Forms | Used by authentication and data-change flows. |
| Theme | Visual token set controlling colors, surfaces, navigation, and action states. | Light/dark theme | Current accents are blue, green, yellow, and red. |
| Responsive design | Layout behavior that adapts to desktop, tablet, and mobile screens. | Responsive UI | Required for web and mobile experiences. |
| Internationalization | Support for multiple interface languages. | i18n | Planned languages: Spanish, English, French, and Portuguese. |
| Angular | Web frontend framework used by web frontend. | Angular 21 | Current web version is Angular 21. |
| React | JavaScript library used as the basis of the mobile frontend. | React | Used together with Expo. |
| Expo | React platform and tooling used for the mobile application. | Expo | Current mobile stack. |
| .NET | Microsoft platform used by several backend services. | .NET | C# microservices in the polyglot stack. |
| C# | Language used by several microservices. | C Sharp | user-management, school, bus, route, configuration. |
| SQL Server | Relational database used for persistent application data (ADR-002). | SQL Server | Main persistence; one instance, schema per service. |
| Docker | Container technology used in project development and deployment workflows. | Containerization | Used with WSL2. |
| WSL2 | Windows subsystem used to support the development environment. | Windows Subsystem for Linux 2 | Part of the local development setup. |
| SENA ADSO | Academic program under which Guardian Escolar is developed. | Análisis y Desarrollo de Software | Cohort/ficha: 3145556. |
| Neiva, Huila, Colombia | Initial geographic and operational context of the project. | Neiva | Determines the initial deployment and domain assumptions. |
| Conventional Commits | Commit message convention using types such as `feat`, `fix`, `style`, `docs`, and `refactor`. | Conventional Commits | Used with the Git workflow. |
| `develop` branch | Git branch used for ongoing development integration. | Development branch | Part of the repository workflow. |
| `docs` branch | Git branch used for documentation work. | Documentation branch | Part of the repository workflow. |

## Naming rules

- Use `Parent/Guardian` in English documentation and `padre/acudiente` when referring to the Spanish domain label.
- Keep route paths, API endpoints, component names, module names, roles, and CSS variables exactly as implemented.
- Use `SUPER_ADMIN` and `ADMIN` for role identifiers in code and contracts.
- Use `student`, `vehicle`, `route`, and `stop` consistently in English technical documentation.
- When a term changes meaning across product and implementation, document both meanings here before updating other documents.
